## 個人情報を git に入れない（leakguard） / Keep personal information out of git
- **private リポジトリ**（`.leakguard-profile` が `private` で、GitHub 上で private と確認できるもの）では、PC名・ホスト名、ローカルIP、Tailscale IP、機器構成を書いてよい。メールアドレス・ホームディレクトリのパスはフックが止める。**API キー・トークン・パスワード・秘密鍵は書かない**。In a private repository (`.leakguard-profile` = `private`, confirmed private) host names, local IPs, Tailscale IPs and hardware specs may be written; never write secrets.
- **public・不明のリポジトリ**では、実名（ホスト名・ユーザー名・実 IP・実メール・ホームディレクトリのパス）をコード・文書・テスト・コミットメッセージに書かない。仮名を使う（`prod-server` / `gpu-pc-1` / `sshuser` / `192.168.1.20` / `100.64.0.10` / `dev@example.com`）。Otherwise never write real host names, user names, IPs, e-mail addresses or home-directory paths into files, tests, docs or commit messages; use those placeholders.
- **push しないリポジトリ**（例: Obsidian の Vault）は `git config leakguard.nopush true` で印を付ける。印のあるリポジトリではハーネスを入れず、実名を書いてよい（秘密は書かない）。印のあるリポジトリからの push は拒否される。A repository that is never pushed (e.g. an Obsidian vault) is marked with `git config leakguard.nopush true`: no harness, real names allowed (never secrets), and push is refused.
- git のコミット作者は `Dev <dev@example.com>`。本名のメールでコミットしない。Commit as `Dev <dev@example.com>`.
- `git commit` / `git push` は leakguard のフック（pre-commit / commit-msg / pre-push）が検査する。**`--no-verify` やフックの無効化（`core.hooksPath` の変更を含む）は禁止**。ブロックされたら中身を直す。Never bypass the hooks (`--no-verify`, changing `core.hooksPath`); when blocked, fix the content.
- **公開（public）リポジトリへは原則 push しない**。例外は、利用者本人が監査（`audit`）のあとに `leakguard.py approve-publish` を実行した場合だけ（1 回・1 時間・そのコミットのみ）。**エージェントは `approve-publish` を実行しない**。他人のリポジトリには push しない。GitHub の API（`gh api` や MCP のファイル更新ツール）でファイルを書き込んでフックを迂回しない。Do not push to a public GitHub repository (the only exception is a one-time approval the person records with `approve-publish`, which an agent must never run) or to someone else's repository, and and never write files through the GitHub API to get around the hooks.
- 利用者が「公開したい」「OSS にしたい」「public にして」「リリースしたい」と言ったら、手順を聞き返さず、スキル `oss-publish-guard`（無ければ `python ~/.config/leakguard/leakguard.py audit --history` から始める）に従って監査から公開準備までを案内し、最後に利用者が自分で打つ `approve-publish` の 1 行を渡す。
- このリポジトリにハーネスが無い（`.githooks/` と `scripts/leakguard.py` が無い）場合は、`python ~/.config/leakguard/leakguard.py init .` で導入してから commit する。If this repository has no harness, run that command first.

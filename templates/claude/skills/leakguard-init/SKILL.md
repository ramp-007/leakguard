# leakguard-init

The tool lives in the private GitHub repo `leakguard` (local checkout: `D:\make-illust\leakguard`) and, for everyday use, in `~/.config/leakguard/` (copied by `setup-global`). It is a single stdlib Python file. Real names are never written into any repo: they live only in `~/.config/leakguard/words` (all repos) and `<repo>/.leakwords` (git-ignored).

## Add the harness to the current repository
1. `python ~/.config/leakguard/leakguard.py init .` — creates `scripts/leakguard.py`, `.gitleaks.toml`, `.githooks/*`, `.github/workflows/leakguard.yml`, `docs/LEAK_GUARD.md`, ignore rules, sets `core.hooksPath`, and (this repo only) `user.email=dev@example.com` if a real address was configured. Idempotent; prints `+` for created and `!` for kept files.
2. Read the "history scan" line. If it reports problems, show the user the findings and stop: the history must be cleaned (rewrite before the first push) before anything is pushed.
3. Review `git status`, then commit **only the generated files** (never other people's uncommitted work). The commit goes through the new hooks.
4. Never use `--no-verify`. If a hook blocks, replace the real name with a placeholder (`prod-server`, `gpu-pc-1`, `sshuser`, `192.168.1.20`, `100.64.0.10`, `dev@example.com`) and add the real name to `~/.config/leakguard/words`.

## Other commands
- `python ~/.config/leakguard/leakguard.py survey <dir>` — which repositories under `<dir>` have the harness.
- `... init <repo> --update` — refresh generated files after the tool improves (files not generated by leakguard are never overwritten).
- `... setup-global` (run from the leakguard checkout) — update the central copy / git template used for every new `git init` and `git clone`.
- `... all` — scan a repository's full history.

## Rules
- Do not write real host names, user names, IPs, e-mail addresses or home directory paths into files, tests, docs or commit messages; use placeholders.
- NEVER push to a public GitHub repository (or to someone else's repository). The pre-push hook refuses it: asks `gh` for the visibility and also refuses when it cannot confirm private/internal. There is no override; do not look for one.
- Before pushing a repository for the first time, run `... all` and make sure the harness exists.
- The repo's `LOCAL.md` / the user's memory hold the real-name ↔ placeholder mapping; those files are not committed.
